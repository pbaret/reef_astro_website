# SEO rules

## One file owns the head

src/layouts/BaseHead.astro writes every meta, canonical, hreflang and OG
and favicon tag by hand. There are no twitter:* tags: Open Graph is enough to
present a shared URL. No SEO package enters this repo; if a tag is missing,
add it there, readable and diffable. BaseLayout passes its
`title/description/image/type/noindex/translations` props straight through.

- Title: `"Title | Brand"` unless the title already carries the brand, which
  the home title does on purpose. The brand and the separator are in the
  dictionary (`site.name`, `site.separator`), one per language.
- Every page sets a written-for-humans `description`: the dictionary (`seo.*`),
  an activity summary or an article description. `site.description` is the
  fallback for utility pages only.
- Canonical: one URL shape, derived from `trailingSlash: "always"` and from the
  page's own entry in `translations`.
- The single source of the production origin is `site` in astro.config.mjs
  (a placeholder, https://example.com, to replace). It feeds canonical, OG,
  sitemap and robots.txt at once; never hardcode the domain elsewhere.

## Multilingual tags

Every indexable page declares `hreflang` for `en`, `fr` and `es` plus
`x-default` (the default language), the `html lang` attribute, `og:locale` and
`og:locale:alternate`. All of them, and the language switcher, read the same
`translations` table (one address per language), built in src/js/pages.ts from
src/i18n/routes.ts and, for articles, from the `translationKey` of the news
collection. The head and the switcher therefore cannot disagree.

Addresses are translated (`/fr/actualites/`, `/es/noticias/`), so the sitemap
integration cannot pair languages by path identity. Its `serialize` hook
(astro.config.mjs) re-reads the `<link rel="alternate" hreflang>` tags of the
built page in dist/ and writes those as the sitemap alternates. The head is the
only source, so the sitemap cannot contradict it.

The 404 pages (`/404.html`, `/fr/404.html`, `/es/404.html`) carry no canonical
and no hreflang: the requested address exists in no language. They are
`noindex`.

## JSON-LD: constructors only

Structured data is built with the typed constructors in src/js/schema.ts and
serialized with `jsonLd()` (it escapes `<`). Every URL is absolute (from
`Astro.site`) and nothing is invented: no review, rating, price, address or
person.

- Home: `Organization` + `WebSite`. `sameAs` lists only the profiles of
  `siteData.socials` that are not flagged `placeholder`.
- Activities, gallery, news list, contact: `WebPage`.
- Articles: `BlogPosting` (`dateModified` only if the entry has `updatedDate`,
  never generated at build time; `image` only when the article image is a
  raster). Author and publisher are the Organization.
- Every inner page: `BreadcrumbList`, emitted by PageHero from the SAME list as
  the visible breadcrumb.

The page route (src/pages/[...path].astro) builds the nodes from the same data
as the title and the description (the dictionary or the news entry). Never
hand-write a JSON-LD object in a page.

## The plain-text surface

- src/pages/robots.txt.ts: allow all, absolute sitemap (`/sitemap-index.xml`,
  the file the sitemap integration writes). It is the only robots.txt: there
  is no public/robots.txt.
- The sitemap integration filters out the 404 pages.

## Social networks

Only Instagram, Facebook and WhatsApp, as plain links: no SDK, no pixel, no
third-party script, no twitter:* tag. The URLs live in `siteData.socials` and
the labels in the dictionary (`footer.social`, with an explicit accessible
name). Both the footer and the contact page render the same SocialLinks
component.

## The post-build audit

`pnpm check:seo` (scripts/check-seo.mjs, also `pnpm build:check`) reads dist/
and rewrites nothing. Errors exit with code 1: head, lang, one h1, canonical,
hreflang (existing and reciprocal routes), Open Graph, JSON-LD validity and
consistency with the page, internal links, sitemap and robots.txt. The
production origin it checks against is read from astro.config.mjs.

## Images and indexing

- The share card is ONE IMAGE AND NOTHING ELSE: no title, no domain, no text,
  because the platform writes og:title under the preview. It is a raster file
  (social networks do not read SVG): public/og-default.png, generated by
  scripts/placeholders.mjs. Replace it with your own 1200x630 image. An
  article with a raster image shares that image, cropped to 1200x630 JPEG by
  Astro (`newsShareImage` in src/js/news.ts); with an SVG it falls back to the
  default card. Pages can pass an `image` prop; its alt text is mandatory.
- `noindex` is a prop, not a habit: only the 404 pages use it.
